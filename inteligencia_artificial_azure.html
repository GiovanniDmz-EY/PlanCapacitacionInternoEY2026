1) Fundamentos de Inteligencia Artificial

Conceptos Base

IA, ML, DL y Aprendizaje Automático

  • Inteligencia Artificial: disciplina amplia para crear sistemas capaces de percibir, razonar y actuar.
  • Machine Learning: subcampo que aprende patrones a partir de datos.
  • Deep Learning: redes neuronales profundas para tareas complejas como visión y lenguaje.
  • IA Generativa: modelos que crean texto, imagen, código u otros contenidos.
Tipos de Aprendizaje

Supervisado, no supervisado y por refuerzo

  • Supervisado: clasificación y regresión usando datos etiquetados.
  • No supervisado: clustering y descubrimiento de patrones sin etiqueta.
  • Refuerzo: agentes que aprenden por prueba/error con recompensas.
Responsible AI

Principios de IA Responsable (Microsoft)

Diseño y operación de soluciones de IA bajo seis principios que guían todo el ciclo de vida del modelo:

  • Equidad: reducir sesgos injustificados y evaluar impactos en distintos grupos de usuarios.
  • Confiabilidad y seguridad: asegurar funcionamiento consistente, robusto y seguro ante errores o uso indebido.
  • Privacidad y seguridad de datos: proteger la información personal y aplicar controles de acceso y gobierno de datos.
  • Inclusión: diseñar experiencias que contemplen diversidad de contextos, capacidades y perfiles.
  • Transparencia: comunicar qué hace el sistema, sus alcances, limitaciones y criterios de decisión.
  • Responsabilidad: definir responsables, procesos de supervisión y mecanismos de corrección continua.

2) Oferta de servicios de IA en Azure (vista ejecutiva)

Nivel 1

Modelos listos para usar

Servicios preentrenados consumibles por API/SDK para escenarios de visión, lenguaje, voz y documentos, minimizando tiempo de salida a producción.

Nivel 2

Servicios para personalización

Capacidades para adaptar modelos con datos de negocio: por ejemplo, Custom Vision, modelos custom de Document Intelligence o personalización de lenguaje.

Nivel 3

Modelos base y MLOps

Gobierno del ciclo completo en Azure Machine Learning: datasets, etiquetado, entrenamiento, evaluación, despliegue, monitoreo y versionado.

Modalidades de ejecución: nube vs local/edge

Ejecución en nube

Escalabilidad y servicios administrados

  • La mayoría de servicios de Azure AI se consumen directamente en la nube con administración completa del servicio.
  • Permite escalar demanda, acelerar despliegues y reducir carga operativa de infraestructura.
  • El esquema de costos depende del consumo, tipo de modelo, capacidad y región.
Ejecución local / edge

Dos rutas principales para operar local

  • Ruta A - Contenedor oficial de Azure AI: se ejecuta localmente (Docker/Kubernetes), pero reporta metrado de uso para facturación.
  • En el esquema estándar de contenedores, el host debe tener conectividad a internet para comunicarse con Azure y enviar datos de medición.
  • Ruta B - Exportación de modelo para edge: se exporta el modelo entrenado para inferencia local en dispositivo, sin correr el contenedor administrado del servicio.
  • En ambos casos aplican restricciones de hardware (CPU/GPU, memoria, almacenamiento y aceleradores disponibles).
  • Siempre se debe validar costos: consumo cloud, costos de contenedor/uso y costos operativos de infraestructura local.
Precisión importante

Conectividad, modalidad desconectada y ejemplo

  • Los contenedores de Azure AI requieren red para metering en el modelo estándar.
  • Existe modalidad de contenedores desconectados para algunos servicios, sujeta a aprobación y esquema de precios por compromiso.
  • Ejemplo: en Custom Vision se puede elegir tipo de modelo orientado a exportación, pensado para correr en dispositivos edge según el escenario.

3) Azure AI Vision y Document Intelligence

Este bloque se divide en tres piezas: Azure AI Vision para capacidades visuales generales, Custom Vision para entrenamiento de modelos propios y Document Intelligence para extracción documental avanzada.

Azure AI Vision (el sentido de la vista)

  • Capacidades out-of-the-box: image analysis para clasificación, detección de objetos comunes, descripción de imágenes y detección de marcas/logos.
  • OCR: extracción de texto simple desde fotos, capturas o documentos visuales.
  • Capacidades avanzadas (Face Service): reconocimiento facial, verificación de identidad y liveness detection para distinguir una persona real de una imagen.
  • Capacidades avanzadas (Spatial Analysis): analítica de video en tiempo real para conteo de personas, tiempos de permanencia y detección de ingresos a zonas restringidas.
  • Cambio clave: para clientes nuevos, los modelos personalizados ya no se entrenan dentro de este servicio; se gestionan en Custom Vision.

Custom Vision (modelos personalizados)

  • Alcance: entrenamiento de modelos de clasificación y detección de objetos con datos de negocio.
  • Nota de plataforma (desde 2025): el entrenamiento custom se centraliza aquí; en esquemas anteriores puede existir soporte solo para implementaciones ya existentes.
  • Flujo de datos: carga de imágenes/video, etiquetado y validación previa al entrenamiento.
  • Criterios de etiquetado: definir reglas consistentes (objeto parcial/completo, borroso/nítido, borde de caja y región anotada).
  • Balance de clases: evitar distribuciones extremas (por ejemplo, pocas muestras en una clase y muchas en otra) para reducir sesgo y mejorar aprendizaje.
  • Auto-etiquetado: acelera trabajo, pero exige revisión humana para verificar calidad y coherencia con el criterio del equipo.
  • Entrenamiento y predicción: se configuran recursos para train/predict según carga y costo computacional.
  • Iteraciones y publicación: una iteración entrenada no queda disponible en producción hasta publicarla.
  • Versionado: la publicación genera una versión; si cambia la versión activa, la aplicación consumidora debe actualizar referencia/configuración.

Azure AI Document Intelligence

  • Modelos pre-built: facturas, recibos, IDs y otros documentos frecuentes para extracción inmediata.
  • Layout (estructura y estilo): identifica tablas complejas, párrafos, códigos de barras y atributos de formato como fuente, tamaño, color y estilos (negrita/itálica).
  • Modelos custom: entrenamiento para formularios internos o documentos propios de la empresa.
  • Clasificación documental: decide automáticamente el tipo de documento antes de leerlo, reduciendo errores de procesamiento.
  • Valor de negocio: conecta papel/PDF con plataformas de BI para acelerar operaciones de onboarding, KYC y backoffice.
Arquitectura y Gobierno de Datos

Auditoría, trazabilidad y retención: diseño fuera del servicio

  • Punto clave: servicios como Vision, Document Intelligence y Custom Vision exponen resultados y métricas operativas, pero no sustituyen una estrategia empresarial de almacenamiento/auditoría.
  • Implicación arquitectónica: si se requiere evidencia, reentrenamiento o trazabilidad, el proyecto debe almacenar de forma explícita entradas (imágenes/documentos) y salidas (JSON/respuestas) en su propio repositorio de datos.
  • Patrones recomendados: Data Lake/Blob para archivos fuente, base documental o tablas para respuestas estructuradas, y repositorios de embeddings/vectoriales cuando aplique búsqueda semántica.
  • Decisiones con cliente: definir qué datos se guardan, cuáles no, periodo de retención, controles de acceso, cifrado, anonimizado y costo total de almacenamiento.
  • Planeación de modelos custom: sin datos suficientes y balanceados por clase, entrenar no es viable ni costo-efectivo; se debe contemplar esta preparación en cronograma y expectativas del proyecto.
  • Regla práctica: para Custom Vision suele recomendarse un mínimo operativo por categoría (comúnmente del orden de decenas, por ejemplo 50+) antes de esperar resultados estables.

4) Lenguaje, NLP y Speech

Esta capa cubre el entendimiento de texto, voz e intención. El servicio "entienda", primero normaliza, descompone y ordena la información para poder interpretarla correctamente.

Procesamiento de texto: limpieza y orden

  • Normalización: prepara el texto para reducir ruido y manejar variantes comunes. En español, el contexto ayuda a distinguir casos donde una tilde cambia el sentido.
  • Lematización: lleva palabras como "corriendo", "corrió" o "correremos" a su forma base para evitar entrenar decenas de variantes del mismo verbo.
  • Tokenización: divide el texto en piezas más pequeñas para que el sistema pueda tolerar errores de dedo y reconocer patrones parciales.
  • Capacidades de Azure AI Language: sentimiento, resumen, extracción de entidades, clasificación y detección de PII.
  • Custom NER: entrenamiento de entidades de negocio (productos, códigos internos, terminología técnica).

Lógica NLU: intenciones y entidades

  • Intención: representa lo que el usuario quiere hacer. Ejemplo: "Quiero comprar un boleto" se interpreta como una acción tipo comprar ticket.
  • Entidad: aporta el detalle sobre el que recae la acción, como ciudad, fecha, producto o persona.
  • CLU: Conversational Language Understanding es la capacidad para modelar intenciones y entidades en experiencias conversacionales.
  • Variaciones regionales: el servicio contempla diferencias como tuteo y voseo para mapear peticiones equivalentes con distinta expresión lingüística.
  • Evolución de plataforma: CLU reemplaza escenarios clásicos previamente asociados con LUIS.

Procesamiento de voz: de ondas a datos

  • Speech to Text: aplica normalización de audio para reducir ruido, estabilizar volumen y enfocarse en la voz humana.
  • Identificación de idioma: puede detectar idioma automáticamente, pero en proyectos se recomienda fijarlo cuando sea posible (por ejemplo, es-MX) para mejorar precisión.
  • Text to Speech: usa voces neuronales que generan entonación más natural que los enfoques clásicos de fragmentos grabados.
  • SSML: permite controlar pausas, tono, velocidad e intención expresiva de la voz sintetizada.
  • Custom Neural Voice: personalización de voz para construir identidad sonora de marca, sujeto a gobierno y aprobaciones.
Mundo Real

¿Por qué falla la IA de lenguaje o voz?

  • Falta de contexto: frases demasiado cortas como "sí" no ofrecen suficientes tokens para interpretar la intención real.
  • Ambigüedad: la polisemia del español exige ejemplos suficientes para separar significados distintos de una misma palabra.
  • Mala calidad de audio: eco, música de fondo o ruido extremo empujan la normalización acústica a su límite.
  • Diseño de entrenamiento pobre: ejemplos poco variados o entidades mal definidas afectan directamente la precisión del modelo.
Enfoque de Consultoría

Qué conviene explicar al cliente o al equipo

  • Language: se usa cuando la meta es entender texto, detectar patrones o extraer estructura semántica.
  • Speech: se usa cuando el desafío principal es capturar o generar voz con calidad operacional.
  • Diseño correcto: antes de hablar de modelos, hay que fijar idioma, contexto de uso, ejemplos representativos y criterios de calidad del audio o texto.

Seguridad de Contenido

Azure AI Content Safety

  • Propósito: analizar contenido explícito, agresiones, odio, violencia o autolesión en texto e interacciones digitales.
  • Enfoque: no depende solo de listas negras de palabras; usa modelos para interpretar contexto, tono e intención del mensaje.
  • Categorías principales: Hate, Self-harm, Sexual y Violence.
  • Severidad: devuelve niveles de riesgo para que la solución decida cómo responder según la política del negocio.
  • Uso práctico: en un bot o transcripción bancaria se puede detectar un insulto y elegir entre detener la conversación, escalar a un agente humano o enmascarar la grosería en el log de auditoría.

5) Azure OpenAI y Foundry (razonamiento generativo)

Modelos generativos

  • Azure OpenAI: acceso empresarial a modelos como GPT-4o y otros LLMs con controles de seguridad y cumplimiento.
  • Capacidad multimodal: generación y comprensión de texto/imagen según el modelo (por ejemplo, DALL-E para imagen).
  • Casos de uso: copilotos internos, asistentes de conocimiento y automatización de procesos cognitivos.

Personalización con RAG y agentes

  • RAG: conecta el modelo a fuentes internas (manuales, políticas, bases de datos) para responder con la "verdad" de la empresa.
  • Azure AI Search: capa de indexación y recuperación semántica/vectorial para sustentar respuestas confiables.
  • Agentes: componentes que no solo responden, sino que ejecutan tareas como consultar stock, crear tickets o agendar citas.

6) Machine Learning Studio y ciclo de vida de modelos

Esta capa aplica cuando se necesita propiedad total del modelo o cuando los servicios preentrenados no cubren el caso: regresiones, clustering, clasificación estadística u otros modelos matemáticos de negocio.

Preparación de datos

Ingesta, limpieza, etiquetado y versionado de datasets para garantizar calidad y trazabilidad desde el inicio.

Entrenamiento

Desarrollo en Notebooks (Python) o con AutoML para encontrar el mejor enfoque algorítmico con evaluaciones reproducibles.

Despliegue y operación

Publicación en endpoints, control de versiones, monitoreo de deriva/desempeño y gobierno de reentrenamiento en producción.
